02

Templates vs. instances

Two different things share the word "form," and mixing them up is the most common source of confusion.

Template
The reusable blueprint — its fields, layout, and rules. Designed once on the Templates screen, then reused every time someone fills it out.
Instance
One filled-out copy of a template. Created on the Fill a Form screen. Every instance becomes a real, filed PDF document in the DMS repository.

A template only produces instances once it's Active — see Publishing a template for the draft → active lifecycle.

03

Building a template

On the Templates screen, New template opens the builder. Everything here is saved as a draft first — nothing is publicly usable until you publish it.

  1. Name it and add fields

    Give the template a name and, optionally, a category (a free-text label for grouping — e.g. "HR" or "Procurement"). Then use Add field to build out the fields your form needs, one row per field.

  2. Decide what the form is laid over

    See Starting from a PDF, image, or blank page below — you can overlay fields on an existing document, or generate a clean page from scratch.

  3. Group fields into sections (optional)

    Use Add section to create labeled groups (e.g. "Applicant details", "Manager approval"). Assign each field to a section from its row's section dropdown. Fields with no section render under a plain "General" heading.

  4. Add validation and conditional logic (optional)

    See Sections & conditional fields — most fields support extra rules beyond just "required."

  5. Decide whether filled-out copies need approval

    The "Filled instances require approval (chain)" checkbox at the bottom controls what happens the moment someone submits a filled-out copy. Leave it off and a filled form files immediately. Turn it on and every submission is automatically routed through the approval engine before it's considered final — useful for anything that needs a manager's sign-off (leave requests, expense claims, procurement forms).

  6. Check the live preview, then create

    The panel on the right (see Reading the live preview) shows the actual PDF that will be generated. Once it looks right, Create template saves it as a draft.

Starting from a PDF, image, or blank page

The Base file panel is optional. Skip it and your fields lay out on a clean, generated A4 page. Upload a file and your fields overlay on top of it instead — handy for pre-printed letterhead, an official government form, or a scanned document you need to annotate.

Accepted formats: .pdf, .png, .jpeg/.jpg. An uploaded image is automatically wrapped into a one-page PDF behind the scenes — you don't need to convert anything yourself first.

!Word documents aren't supported

Uploading a .doc/.docx file will be rejected with a message asking you to export it to PDF first (or upload a PNG/JPEG of it). Converting Office documents automatically isn't supported yet.

Field types

Every field row has a type dropdown. This determines what input the person filling out the form sees — not how it's drawn in the final PDF, which is always rendered as formatted text regardless of type (see What was fixed for why that's the right call).

Sections & conditional fields

Each field row has a "Show this field only if" control. Click Add condition to make a field appear only when another field's value equals, doesn't equal, or contains something you specify — for example, showing a "Reason for rejection" field only when a "Decision" dropdown is set to "Rejected." Hidden fields aren't required even if marked required, and this same rule is enforced again on the server when the form is submitted, so it can't be bypassed by editing the page.

Reading the live preview

The panel on the right of the builder isn't a mockup — it is the PDF.

Every time you add or edit a field, the builder asks the server to render the exact same PDF pipeline used for real submissions, filled with placeholder sample values, and shows the result in the preview pane a half-second later. If the layout, spacing, or base-file background looks off in the preview, that's exactly how the real generated document will look too — so it's worth fixing here rather than discovering it after someone's filled the form out for real.

04

Publishing a template

A new template starts as a draft and isn't available on the Fill a Form screen until it's Active.

Draft→ Pending approval→ Active→ Deprecated
  • Draft — editable, invisible to everyone except template managers. Not yet on the Fill a Form list.
  • Submit for approval — from a draft's row, this sends it through the same approval engine used elsewhere in DMS. Expand Approval status on its row to see where it sits in the chain.
  • Active — the chain approved it. It now appears on the Fill a Form screen and can be filled out.
  • New version — available once a template is Active or Deprecated. Clones it into a fresh draft you can edit and resubmit, without touching the published version everyone's currently using.
  • Deprecate — removes an Active template from the Fill a Form list without deleting its history. Existing filed instances are unaffected.
→Filtering the list

The status pills across the top of the Templates screen (All / Draft / Pending approval / Active / Deprecated) filter the list — useful once you have more than a handful of templates.

05

Filling out a form

On the Fill a Form screen, every card is an Active template. Click one to open it.

  1. Pick a template

    Only Active templates are listed. If the one you need is missing, it's likely still in draft or pending approval — ask whoever manages templates.

  2. Fill in the fields

    Required fields are marked; conditionally-hidden fields only appear once their trigger condition is met. For a "file upload" field, attach the actual file here — it's filed as its own document alongside the generated form.

  3. Choose a department (if asked)

    This determines which department the generated document is filed under in the DMS repository.

  4. Submit

    This generates the real PDF and files it as a document. If the template requires chain approval, you'll see a note that it's now routed for approval rather than immediately final. Either way, you're taken straight to the new document's page, where the generated PDF is ready to preview.

06

Tracking your submissions

My Submissions lists every form you have personally filled out, most recent first, with its approval progress if it has any.

This is a personal list, not a management view — it only shows instances you created. Expand an entry to see its approval chain the same way you would on a template pending approval.

07

What was fixed

If PDF generation used to fail on you — on both uploaded-PDF templates and fully manual ones — here's what was actually wrong and why it's resolved now.

✓Root cause

The PDF-rendering engine only ships one guaranteed renderer out of the box — plain text. Fields typed as date, number, checkbox, or long text were being handed to renderers that no longer existed in the installed version, so generation threw an error before producing anything, on every template regardless of whether it was built on an uploaded PDF or from scratch.

✓The fix

Every field now renders through that one reliable text renderer, formatted appropriately for its type (checkboxes print as "Yes"/"No", numbers and dates print as their entered value). Nothing about how you build a template changed — this was purely a rendering-pipeline fix, verified against a template containing one field of every type.

✓Preview now matches reality

The old preview was a rough HTML approximation that didn't reflect real spacing or the base file background. It's since been replaced with the actual generated PDF, rendered with sample data — see Reading the live preview.

✓Base files beyond PDF

Base-file upload previously rejected anything that wasn't a PDF outright. PNG and JPEG are now accepted too, wrapped into a PDF automatically — see Starting from a PDF, image, or blank page.

08

Troubleshooting

"Failed to generate form PDF" when filling out a form

This was the bug described above and should no longer occur. If you still see it, it's a new issue, not the old one — check whether a required field with a conditional ("show only if") rule is hidden but still marked required with no value; that specific combination can still trip up generation and is worth reporting.

My new template doesn't show up on Fill a Form

Only Active templates appear there. Check its status on the Templates screen — it's likely still a draft or waiting on its approval chain.

The base file I want to use is a Word document

Export it to PDF first (any word processor can do this from its Print/Export menu), or take a screenshot/scan as a PNG or JPEG — both are accepted directly.

The live preview looks broken or won't load

It briefly shows "Rendering…" after every edit — that's expected, it's regenerating the real PDF. If it shows a persistent error message instead, the schema it's trying to render has a problem (most often a required field hidden by a condition, per above); the error text names what failed.
